게임과 함께 설계한 조작 동작

새로운 입력 장치가 플레이 방식을 어떻게 바꿀 수 있는지 탐구하고자 프로젝트를 제안했습니다. 왼손은 고삐, 오른손은 올가미를 조작하도록 게임과 컨트롤러를 함께 기획했습니다.

상명대학교 미래설계학점으로 진행한 자체 설계 프로젝트입니다. 팀원들은 게임 구현과 3D 에셋을 담당했으며, 캐릭터 조작 연결은 협업했습니다.

왼손: 의도한 동작과 다른 축의 움직임 구분

9주차 시험에는 정상 입력과 함께 원하지 않은 동작도 기록되어 있습니다. 보관된 펌웨어는 중력을 추정해 제거한 뒤 샘플 사이 선형가속도의 차이를 사용합니다. 주축의 변화가 기준을 넘고 다른 축은 제한값 이하일 때 동작을 받아들입니다.

  • 교차 축 입력 배제동작 중 다른 조작이 함께 인식되는 것을 제한.
  • 유지 시간과 재입력 간격키를 누르는 시간과 다시 입력할 수 있는 시점을 제어.
  • 명시적 키 해제타임아웃이나 최대 유지 시간이 지나면 눌린 키를 해제.

코드에서는 “jerk”라는 변수명을 쓰지만, 시간 간격으로 나누지 않은 샘플별 가속도 차이입니다.

오른손: 회전 이후의 던지기 판별

단순히 가속도가 커졌다는 이유만으로 던지기로 판단하지 않습니다. 대기/회전 상태를 구분하고, 가속도 피크 뒤에 각속도가 감소하는 순서를 확인합니다. 회전을 유지하는 동안에는 게임의 올가미 조작에 연결되는 클릭을 반복 전송합니다.

  • 회전 시작각속도가 적응형 임계값을 넘으면 마우스 오른쪽 버튼을 유지.
  • 회전 유지오른쪽 버튼을 유지하면서 왼쪽 클릭을 반복 전송.
  • 던지기최소 350 ms 회전 후, 가속도 피크가 감지되고 200 ms 안에 각속도가 감소하면 버튼 해제 가능.

각속도가 피크 감지 시점 값의 0.35배 아래로 내려가는 조건을 사용합니다. 별도의 회전 종료·타임아웃 경로도 버튼을 해제합니다. 이는 구현값이며 인식 정확도를 측정한 결과는 아닙니다.

개발 기록에 남은 두 가지 연결 문제

  • IMU 초기화 실패

    가정했던 보드·센서 조합이 실제 하드웨어와 달랐습니다. Nano 33 BLE Rev2임을 확인하고 BMI270/BMM150 라이브러리로 센서값 수신을 확인했습니다.

  • 연결 전에는 정상으로 보였던 전원

    무부하 상태의 5 V 측정값만으로는 손상된 승압 모듈을 발견하지 못했습니다. 보드에서 직접 측정하고 220 Ω 부하 시험을 진행해 역연결 이후의 고장을 확인했습니다.

게임 및 컨트롤러 시연

프로젝트의 결과와 다음 질문

두 무선 프로토타입으로 게임을 조작하는 결과물을 제작했습니다. 게임 구상, 컨트롤러 조립, 동작–입력 매핑과 연결 작업을 맡았습니다. 시험 기록에는 입력 간섭과 이에 대응한 수정이 남아 있지만, 인식률이나 지연 성능을 측정한 결과는 없습니다.

이 프로젝트는 게임에 행동을 전달하는 방식을 바꿨습니다. 이후에도 반응이 주로 시각에 머문다는 문제의식이 PGI의 손끝 피드백 장치로 이어졌습니다.
