말의 이동과 올가미 조작을 위한 왼손·오른손 전용 동작 컨트롤러

시연 영상입력 설계동작 인식코드

게임과 입력 장치를 함께 설계

새로운 입력 장치로 플레이하는 게임을 팀에 제안했습니다. 게임을 기획하고 컨트롤러를 제작했으며, 손동작을 게임 입력에 연결했습니다.

왼손으로 말을 움직이고, 오른손으로 올가미를 돌려 던집니다. 동작 인식은 각 컨트롤러에서 처리합니다.

게임과 컨트롤러 시연

손동작을 게임 입력에 연결하는 방법

  1. 왼손 · 말 이동좌우로 움직이기 → 방향 조작아래로 짧게 흔들기 → 말을 앞으로 몰기BLE 키보드 입력
  2. 오른손 · 올가미원을 그리며 움직이기 → 올가미 돌리기던지는 동작 → 올가미 놓기BLE 마우스 입력

Arduino Nano 33 BLE Rev2 2개 · 관성 측정 장치(IMU) · BLE HID

동작별 키보드·마우스 입력
왼손 · 말 이동축별 동작 인식BLE 키보드 입력 · A/D, Shift, W→S 순차 입력
오른손 · 올가미돌리기 → 유지 → 던지기BLE 마우스 입력 · 오른쪽 버튼 누름 유지, 왼쪽 버튼 반복 클릭, 버튼 해제

배터리로 구동하는 시제품 두 대를 제작했습니다. 각 시제품에는 Arduino Nano 33 BLE Rev2, 리튬 폴리머 배터리, 충전·승압 회로와 전원 스위치가 들어갑니다.

동작 센서가속도 · 각속도
컨트롤러 펌웨어동작 판정 · 입력 상태BLE HID
Unreal Engine말 이동 · 올가미 조작

두 컨트롤러는 PC에 키보드와 마우스로 인식됩니다. 장치가 동작을 판정해 입력 이벤트를 보내면, 게임은 기존 입력 시스템을 통해 해당 동작을 처리합니다.

의도하지 않은 입력을 줄이는 방법

왼손

가속도에서 중력 성분을 제거하고 축별 변화량을 비교합니다. 키를 누르는 시간, 재입력 대기 시간, 키 해제 조건을 구분해 입력이 의도치 않게 반복되는 것을 줄였습니다.

오른손

올가미를 돌리기 시작한 뒤 처음 350 ms 동안은 던지기로 판정하지 않습니다. 이후 가속도가 기준값을 넘는 순간의 각속도를 기준으로 삼습니다. 그 뒤 200 ms 안에 각속도가 이 값의 35% 미만으로 떨어지면 던지기로 판정합니다.

위 수치는 펌웨어에서 사용하는 판정 조건입니다. 인식 정확도나 지연을 측정한 값은 아닙니다.

왼손 동작 판정과 펌웨어 발췌

9주차 테스트에서는 정상 입력과 함께 원하지 않은 동작도 발생했습니다. 공개한 펌웨어는 중력 성분을 추정해 빼고, 연속된 두 샘플 사이의 선형 가속도 변화량을 비교합니다. 주축에서 기준값을 넘으면서 나머지 축은 각 기준 이하일 때만 동작을 입력으로 처리합니다.

  • 다른 축의 움직임 검사한 동작을 수행할 때 다른 동작이 함께 인식되는 것을 줄입니다.
  • 키 유지와 재입력 대기키가 눌린 상태를 유지하는 시간과 다시 입력을 받을 수 있는 시점을 정합니다.
  • 키 해제 처리타임아웃 또는 최대 유지 시간에 도달하면 눌린 키를 해제합니다.

코드에서는 jerk라는 변수명을 쓰지만, 실제 계산값은 경과 시간으로 나누지 않은 샘플 간 가속도 차이입니다.

오른손 상태 전환과 던지기 판정

던지기는 가속도가 한 번 급격히 변하는 것만으로 판정하지 않습니다. 대기·회전 상태를 관리하면서, 가속도가 기준을 넘은 뒤 각속도가 떨어지는 순서까지 확인합니다. 회전을 계속하면 왼쪽 클릭을 반복해 게임에서 올가미가 돌도록 합니다.

  • 회전 시작각속도가 적응형 기준값을 넘으면 마우스 오른쪽 버튼을 누른 상태로 유지합니다.
  • 회전 유지오른쪽 버튼을 누른 상태에서 왼쪽 클릭을 반복해서 보냅니다.
  • 던지기회전 시작 후 350 ms가 지나야 판정합니다. 가속도가 던지기 기준을 넘은 시점부터 200 ms 안에 각속도가 그 시점 값의 35% 미만으로 떨어져야 올가미를 놓습니다. 이 조건으로 회전을 시작하는 동작과 던지는 동작을 구분합니다.

동작 정지 또는 타임아웃으로도 버튼이 해제됩니다. 각 기준값은 구현 설정이며, 인식 정확도는 별도로 측정하지 않았습니다.

연동 과정에서 해결한 문제

처음에는 보드의 센서를 잘못 파악해 IMU가 초기화되지 않았습니다. Rev2 보드임을 확인하고 BMI270/BMM150 라이브러리를 적용해 센서 값을 읽을 수 있었습니다.

보드 식별과 전원 문제 진단

  • IMU 초기화 실패

    가정했던 보드·센서 조합이 실물과 달랐습니다. 보드가 Nano 33 BLE Rev2임을 확인한 뒤 BMI270/BMM150 라이브러리를 사용하자 센서 값을 정상적으로 읽었습니다.

  • 부하가 없을 때는 전압이 정상으로 보임

    무부하에서는 5 V가 나왔지만 승압 모듈이 손상된 상태였습니다. 역결선 이후 보드에서 전압을 측정하고 220 Ω 부하를 연결해 시험하면서 문제를 찾아냈습니다.

결과와 담당 범위

완성된 게임을 무선 시제품 두 대로 조작할 수 있었습니다. 게임 기획, 장치 제작과 입력 연동을 맡았으며, 인식 정확도와 지연은 측정하지 않았습니다.

개인 기여와 펌웨어의 한계

게임 콘셉트를 구상하고 컨트롤러를 조립했습니다. 손동작과 게임 입력의 대응 관계를 정하고 연동에 참여했습니다. 테스트 기록에는 입력이 겹쳐 오작동한 사례와 이를 줄이기 위해 수정한 내용이 남아 있습니다.

한계

인식 정확도와 지연은 측정하지 않았습니다. 펌웨어는 직접 정한 설정값과 올가미 동작의 적응형 기준값을 함께 사용합니다. 사용자와 그립이 달라져도 같은 방식으로 작동하는지는 평가하지 않았습니다. BLE HID로 보내는 것은 키보드와 마우스 이벤트입니다. 회전 속도에 따라 클릭 간격은 바뀌지만, 손 자세나 원시 IMU 데이터가 게임에 연속적으로 전달되지는 않습니다.

후속 작업 아이디어

아래는 아직 구현하거나 평가하지 않은 방향입니다.

  • 인식률과 지연 평가동작에 정답 라벨을 붙여 원시 IMU 데이터를 기록하고, 인식률, 오인식, 동작부터 입력까지 걸린 시간을 측정합니다.
  • 사용자별 보정현재의 적응형 판정 기준에 더해, 사용자마다 다른 동작 범위를 반영하는 짧은 보정 절차를 시험합니다.
  • 연속 입력게임에서 연속적인 동작 값을 쓸 수 있도록 커스텀 HID나 시리얼 인터페이스를 검토합니다.

이 프로젝트에서는 플레이어의 동작이 게임에 들어가는 방식을 바꿨습니다. 게임의 반응은 주로 화면으로 전달됐고, 그 반응을 손끝으로 전달할 수 있을지 고민하면서 다음 작업인 PGI 피드백 시스템으로 이어졌습니다.
